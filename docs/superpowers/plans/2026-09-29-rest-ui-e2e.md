# REST, UI Integration, and Booking E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the verified booking core through the versioned REST contract, connect the Next.js interface through a generated TypeScript client, render durable appointment URLs, and prove the complete browser-to-PostgreSQL booking journey.

**Architecture:** Go HTTP handlers validate and map transport data to the existing application services and PostgreSQL repository. A generated TypeScript client is the only browser API adapter. Successful confirmation navigates to a server-rendered appointment route that retrieves durable state from the Go API; Playwright exercises the Compose network from a clean database.

**Tech Stack:** Go 1.27 `net/http`, `pgx/v5`, OpenAPI 3.1, generated TypeScript fetch client, Next.js 16 App Router, React 19, Playwright, Docker Compose.

**Spec:** `openspec/changes/bootstrap-service-scheduler/design.md`; observable behavior is in `openspec/changes/bootstrap-service-scheduler/specs/service-appointment-booking/spec.md`.

## Global Constraints

- Generated files, fixtures, routes, UI copy, logs, and commits must not identify the organization that supplied the source brief.
- JSON errors use stable uppercase codes, safe messages, request identifiers, and field details only for validation failures.
- API timestamps require an explicit offset; persisted output is serialized as RFC3339 UTC.
- Availability remains advisory; confirmation always revalidates and may return `RESOURCE_CONFLICT`.
- The browser never connects to PostgreSQL and never substitutes local storage for appointment retrieval.
- The Go API owns backend behavior; Next.js remains presentation and server rendering only.
- Production hosting remains undecided; local Compose is the only deployment target in this slice.

## Review Focus

- Malformed JSON, duplicate JSON keys, unknown properties, oversized bodies, invalid UUIDs, missing idempotency keys, and trailing path segments must return stable safe errors.
- CORS preflight and error responses must preserve request IDs and allow only the configured exact origin.
- A client disconnect or database outage must cancel work and must not leak connection details.
- The appointment page must distinguish not found from temporary API failure and refetch on a direct URL/reload.
- E2E must select a future fixture date that remains valid without depending on the machine clock or locale.
